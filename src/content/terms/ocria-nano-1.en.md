intro: "**OCRia-nano-1** is LlamaIndex’s lightweight document-parsing model, released on 23 November 2026 as the smallest member of the OCRia family, with **8.1 million** parameters in total. The official post [Introducing OCRia-nano-1](https://www.llamaindex.ai/blog/introducing-ocria-nano-1) is dated that day; [@llama_index](https://x.com/llama_index/status/2124952874316632394) introduced it at 19:46 UTC. Weights are on [Hugging Face llamaindex/OCRia-nano-1](https://huggingface.co/llamaindex/OCRia-nano-1), and the model runs on local CPUs through the open-source parser **LiteParse**.\n\nLlamaIndex positions it as the default first pass over an organization’s document collection—reading text, reconstructing tables, and recovering layout—even if the hardest pages still need a larger vision-language model. It combines seven specialized document models totaling 8.1M parameters, trained with distillation that used OCRia-1 to help generate transcriptions, table annotations, and layout labels.\n"
explain: "## Accuracy and speed\n\nThe official blog places Nano on the accuracy–speed Pareto frontier among the lightweight parsers LlamaIndex evaluated, and says it is more accurate on tables and layout than Marker, PP-OCRv6 tiny, and Tesseract, while running 2–5× faster than default Tesseract OCR.\n\nOn **ParseBench-2**, Nano scores **59.2** overall, including **59.5** on tables. Average processing time is **426 milliseconds** per page on a single core (the full LiteParse pipeline, from text recognition to structure recovery), with 90% of measured pages finishing within **862 milliseconds**. With 16 single-core workers it processes **27.8 pages per second**, about twice the throughput of LiteParse’s default Tesseract configuration. The launch post also says it beat every local CPU parser they tested on all five quality benchmarks. These are vendor-reported figures.\n\n## Pipeline and when to use it\n\nLiteParse starts from text already in the file. Nano’s OCR models recognize text where that layer is missing or unreadable, including scans and embedded images. A table-and-layout model then uses the text, its position, and visual features to recover table structure and content blocks. Output can be Markdown (headings, lists, and reconstructed tables), JSON with bounding boxes, or plain text.\n\nThe OCR recognizers cover Latin, Chinese/Japanese/Korean (CJK), right-to-left, and other scripts. A tiny script router picks each page’s majority script, allows confident line-level overrides, and detects upside-down pages.\n\nLlamaIndex’s guidance: use OCRia-nano-1 for high-volume everyday reports, straightforward contracts, invoices with simple tables, and routine scans; use the larger **OCRia-1** for complex tables, handwriting, heavily degraded scans, and scanned math. If you need chart-to-table extraction, use OCRia-1—Nano has no chart model and keeps charts as images.\n"
