explain: "## 它由哪几部分组成\n\nClaude Ship 由已经正式可用的 **Code Review**，再加上测试中的两个新代理 **PR Steward** 与 **Claude Approvals** 组成。\n\n**Code Review** 从多个角度审查 PR，对发现做对抗核验和分类，再评论到 PR 上。官方称，在 Claude Code 团队内部，把 Claude 的审查作为更广流程中的一层之后，6 月到 9 月合并的 PR 数量增加了一倍以上，被回滚的比例下降了 40% 以上。每个仓库可选 Quick、Standard 或 Deep 审查级别，并用 REVIEW.md 调整要标记的问题。发现会标成 Important、Nit 或 Pre-existing。\n\n**PR Steward** 负责把红的 PR 拉回绿色，但被设计为**不批准、不合并**。它会处理失败的 CI、合并冲突，以及来自 Code Review、其他审查工具或同事的意见。每次推送后都会评论改了什么、如何撤销。开发者可以用 `@claude` 加指令来引导，或用 `@claude stop` 让它停下。\n\n**Claude Approvals** 读取仓库里的策略文件，表现得像更聪明的 CODEOWNERS：策略允许时可以自行批准常规改动，也可以要求更深的人工签字。决策可以参考 Code Review 结论或团队用自然语言写的分类器。官方建议大多数客户先开观察模式，再把分支保护配成必须得到 Claude Approvals 放行。\n\n## 怎么启用，以及限制\n\n开发者可以在 Claude Code 里对当前改动运行新的 `/ship` 命令：Claude 会推送、开 PR、审查并处理反馈与失败检查，最终能否合并仍取决于开发者权限和仓库分支规则。管理员可以按仓库打开 Code Review 和 PR Steward，并配置审查级别、触发时机和支出上限；默认分支上有策略文件时，Claude Approvals 会启动，管理员也可以关掉。它与现有的分支保护和必过检查一起工作。\n\n合格的 Claude Enterprise 组织可领取至少 **1 万美元** 的 Claude Ship 额度，需在领取后 30 天内用完，申请截止 **2027 年 1 月 15 日**，以条款为准。用量按 token 计费；管理员可为 Code Review 和 PR Steward 设置支出上限。Claude Approvals 没有基础费用，但策略里的分类器会按 token 计费，引用 Claude 审查时即使处于观察模式也会产生一次计费的 Code Review。`/ship` 计入常规 Claude Code 用量。\n\nClaude Ship 目前只支持 GitHub 上的仓库，且**不向**使用零数据保留（ZDR）、HIPAA 配置或客户托管加密密钥的组织开放。\n"
