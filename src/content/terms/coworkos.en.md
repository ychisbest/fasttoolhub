intro: "**CoworkOS** is an open-source **cowork harness** from Renmin University’s RUC-NLPIR and collaborators for **long-horizon, human-in-the-loop** productivity work ([repo](https://github.com/RUC-NLPIR/CoworkOS), [project page](https://coworkos-ai.github.io/), [arXiv:2611.03178](https://arxiv.org/abs/2611.03178)). A three-layer runtime separates **Main Agent** (plan / delegate / accept), **Coordinator Runtime** (dispatch and lifecycle), and optional **Subagents**. Hierarchical workspaces, semantic memory, and revision-aware candidate edits stay on your machine so people and agents can co-edit the same documents, presentations, CAD, or Blender scenes.\n\nShip surface includes the **coworkos-app** npm package (desktop install targets Apple Silicon macOS 14+). The paper reports five recursive self-improvement rounds where GLM-5.3 drove post-training of Qwen3.6-35B-A3B, lifting an eight-benchmark average from **33.19 to 42.95**. The public repo landed **2026-11-03**, with X / HuggingPapers discussion continuing into **2026-11-04**."
explain: "## Problem\n\nGeneric chat agents often lose state across long jobs that need human approval, recovery, and shared artifacts. CoworkOS separates **strategy from execution** and keeps workspaces, logs, and editable artifacts so humans and agents can continue the same project across hours or days.\n\n## Differentiation\n\n- Explicit three-layer split: models decide; the runtime coordinates and persists.\n- First-class shared apps (docs, slides, CAD, Blender) with revision-aware candidate changes—not only CLI tool calls.\n- Paper uses the harness itself as an RSI vehicle (stronger model post-trains a weaker one across rounds).\n\n## Limits\n\n- Desktop install docs currently emphasize Apple Silicon macOS; treat other platforms as TBD.\n- Benchmark gains are author-reported; reproduce with matching models, data, and harness versions.\n- Many products use “cowork” in marketing—cite RUC-NLPIR/CoworkOS or the paper title."
