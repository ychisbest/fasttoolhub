intro: "**Microsoft Perception** 是微软在 2026 年 11 月 17 日 Ignite 上宣布一般可用的安全产品名。Tech Community 文章 [What's new with Microsoft Perception at Ignite 2026](https://techcommunity.microsoft.com/blog/perception-blog/whats-new-with-microsoft-perception-at-ignite-2026/4571834) 写得很直接：去年 7 月以 **Project Perception** 提出的设想，在 Ignite 上成为 Microsoft Perception，并进入 GA。同期安全博客 [Security for the agentic era, powered by Microsoft Perception](https://www.microsoft.com/en-us/security/blog/2026/11/17/security-for-the-agentic-era-powered-by-microsoft-perception/) 把它定位为应对“攻击也在用 AI、速度从月缩到分”这一变化的新安全堆栈。\n\n官方描述的不是往旧工具里塞几个 chatbot，而是一套把信号、情报和编排连在一起的 cyber stack：专用模型与 agent 团队在调查、防护和修复之间分工，安全人员设定优先级并对关键动作做批准。红队 agent 负责发现并验证可能的攻击路径，蓝队 agent 分诊告警、调查攻击并把威胁情报变成检测，绿队 agent 找出最重要的暴露面并协调修复。\n\n本条记录的是这次 GA 确认的产品名 Microsoft Perception。不要把它和普通的 Microsoft 365 安全告警功能，或 Ignite 同期宣布的 Copilot 界面改动当成同一个名字。"
explain: "微软把 Perception 写成面向 agent 时代的防守平台。攻击者可以并行、自动地找漏洞和打漏洞，防守若仍按“一条告警、一次调查、一次响应”来做就会跟不上。Perception 的编排 harness 把工作分配给红、蓝、绿三类 agent，并用 playbook 围绕一个具体安全结果把它们组织起来；团队也可以在聊天里描述目标，再通过集成的 session 查看过程与结果。官方强调关键动作仍由人批准。\n\n7 月的 Project Perception 是愿景与项目名，11 月 17 日的宣布是这个名字转正并 GA，同时扩展了 agent 能力。公开材料还把它和“agentic SOC”、以及在环境中持续发现—调查—处置的循环连在一起。具体包含哪些数据源、与 Microsoft Security 其他产品如何集成、哪些租户可以开启，要以官方文档和 Ignite Book of News 当时的说明为准。\n\n不要把 Microsoft Perception 理解成一个新的通用大模型，它是安全向的产品平台。也不要和同场发布的 Copilot Home、MAI 模型系列混为一个词条。"
