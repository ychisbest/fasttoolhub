intro: "**Kinference** (pronounced *kay-inference*) is an **open-source inference control plane** built by **Buoyant**, the company behind the Linkerd service mesh, and announced on the **vLLM blog on 2026-11-04**. The code lives at GitHub `Kinference-AI/kinference`.\n\nIt aims to be the missing layer for building an inference platform on **vLLM and Kubernetes**: point OpenAI- or Anthropic-compatible clients at Kinference's HTTP endpoint and it handles **token rate limiting, per-tenant usage and cost tracking, intelligent load balancing and inference policies**, while vLLM does the actual inference."
explain: "## What problem it solves\n\nTeams self-hosting open-weight models juggle many models, heterogeneous GPU pools and multiple tenants. Standard Kubernetes Service load balancing doesn't understand LLMs, wasting KV cache and making cost control hard.\n\n## Core features\n\n- **KV-cache-aware load balancing**: routes each request to the vLLM worker that will do the least work, using GPU queue sizes, historical performance and modeled KV-cache contents.\n- **Inference policies**: e.g. send simple requests to a cheaper model only when that is less work given the cache state.\n- **Governance**: token rate limiting, tenant usage and cost tracking, metrics and SLOs.\n\n## Official benchmarks\n\n- vs. default Kubernetes Service balancing: **95% lower median TTFT** and 45% lower median end-to-end latency on one workload.\n- Capacity test: **7.4×** goodput on shared-prefix and about **3.5×** on multi-turn workloads.\n\n## Limitations\n\n- Brand-new project; ecosystem and production references are still growing.\n- Requires Kubernetes Gateway API CRDs and vLLM; not for non-K8s setups."
