explain: "## What it is made of\n\nClaude Ship combines **Code Review**, which is already generally available, with two new agents in beta: **PR Steward** and **Claude Approvals**.\n\n**Code Review** reviews a pull request against the codebase through multiple lenses, adversarially verifies findings, categorizes them, and posts them on the PR. Anthropic says that on the Claude Code team, where Claude’s review is one layer in a broader process, merged PRs more than doubled from June to September while the share reverted fell by more than 40%. Each repository can use Quick, Standard, or Deep review, and REVIEW.md can tune what gets flagged. Findings are ranked Important, Nit, or Pre-existing.\n\n**PR Steward** works to keep a PR green and is designed **not to approve or merge**. It jumps in on failing CI checks, merge conflicts, and review feedback from Code Review, other tools, or teammates. After every push it comments with what it changed and how to undo it. Developers can comment `@claude` with an instruction to steer the work, or `@claude stop` to have it step back.\n\n**Claude Approvals** applies an approval policy written as a file in the repository. It works like a smarter CODEOWNERS file: Claude can approve routine changes when the policy allows, or require deeper human sign-off. Decisions can consider Code Review findings or classifiers the team writes in natural language. Anthropic recommends starting in observe-only mode before making Claude Approvals a required branch-protection check.\n\n## How to turn it on, and the limits\n\nDevelopers can try it on their own changes with the new `/ship` command in Claude Code: Claude pushes the change, opens the PR, reviews it, and works on feedback and failing checks. What can actually merge still depends on the developer’s permissions and the repository’s branch rules. Admins enable Code Review and PR Steward per repository, and set review level, when reviews run, and spend limits. Claude Approvals starts when a connected repository has a policy file on its default branch; an admin can turn it off. It works with existing branch protection and required checks.\n\nEligible Claude Enterprise organizations can claim at least **$10,000** in Claude Ship credits to use within 30 days of claiming, by **15 January 2027**, terms apply. Usage is billed on tokens; admins can set spend limits for Code Review and PR Steward. Claude Approvals has no base charge, but classifiers in a policy are billed on the tokens they use, and a policy that uses Claude’s review triggers a billed Code Review even in observe mode. Running `/ship` counts as regular Claude Code usage.\n\nClaude Ship is available for GitHub repositories on Team and Enterprise plans. It is **not available** to organizations with Zero Data Retention, the HIPAA configuration, or customer-managed encryption keys.\n"
