intro: "**GPT-6.2 Astra** 和 **GPT-6.2 Sol** 是 [OpenAI](https://openai.com/index/introducing-gpt-6-2-astra-sol/) 在 2026 年 11 月 17 日正式发布的一对新模型。官方开篇写道：Astra 是“our new frontier model for your hardest projects”，Sol 是“our efficient, versatile model for everyday work”。两者都强调在更少的输出 token 下完成更难的任务，从而在用量限额内做更多事情，并在规模化使用时控制成本。\n\n官方说明：即日起，所有 Plus、Pro、Enterprise 和 Edu 用户可在 **ChatGPT Work** 与 **Codex** 中使用这两个模型；Pro 500 订阅者可以对任一模型使用 Ultrafast，并且官方首次把 Ultrafast 扩展到 Pro 200 档（具体限额以官方说明为准）。开发者文档 [Using GPT-6.2](https://developers.openai.com/api/docs/guides/latest-model) 给出 API 模型 ID：`gpt-6.2-astra` 与 `gpt-6.2-sol`。OpenRouter 目录页 [GPT-6.2 Astra](https://openrouter.ai/openai/gpt-6.2-astra) 与 [GPT-6.2 Sol](https://openrouter.ai/openai/gpt-6.2-sol) 标注 Released Nov 17, 2026，并列出 Astra Pro 是同一底层模型在 `reasoning.mode` 设为 pro 时的服务方式，而不是一条独立的模型品牌。\n\n本轮对 openai.com 站点地图的增量扫描新增了官方介绍页，以及 [Astra for Law](https://openai.com/index/astra-law-6-2/) 更新页。后者写明 Astra for Law 是 GPT-6.2 Astra 的法律配置（扩大法律检索索引并加入研究/权衡/撰写说明），该配置名称已在 2026 年 9 月向部分律所推出，本轮只把 GPT-6.2 Astra / Sol 作为新词收录。"
explain: "官方把 Astra 定位为复杂专业工作的质量标杆：幻灯片、表格和文档更贴近你提供的模板与行业惯例，代码更干净，面向网站、游戏和 3D 设计的前端也更好看、更好用。文中列出的评测包括：在多步专业工作测试 Agents’ Last Exam 上，GPT-6.2 Astra 比 GPT-6 Astra 高 5.2 分，且单任务成本不到其三分之一，同时比 Claude Fable 5.2 高 5.5 分、成本约为其 5%（官方注明 Fable 5.2 的该榜成绩排除了 9 道使用了回退模型的题）；在 Terminal-Bench-Science 0.1 上比 GPT-6 Astra 高 9 个百分点，成本同样不到三分之一，并在 Vals Science Index 上刷新成绩。官方还提到内部 GDPval v2、Harvey LAB-AA、Artificial Analysis 的 AA-AnalystAgent 等知识工作评测。\n\nSol 被写成“many employees at OpenAI use it as their default model”。与 GPT-6.1 Sol 相比，官方称它更聪明、更省，能在同一付费方案下完成更多任务，适合多步智能体工作流和清楚、自然的写作。在 Cognition 的 FrontierCode 2.0 上，GPT-6.2 Sol 在 max 设置下与 GPT-6.2 Astra 相差约 0.5 分，成本约为后者的五分之一；在日常任务评测 LifeVal 上，Sol 的成绩高于 GPT-6 Astra，成本约为其七分之一。\n\nAPI 价格方面，官方写明 GPT-6.2 Astra 的输入和输出 token 单价比 GPT-6 Astra 低 20%，缓存输入再打 60% 折扣：每百万 token 输入 8 美元、缓存输入 0.40 美元、输出 40 美元。GPT-6.2 Sol 保持 GPT-6.1 Sol 的 API 单价。OpenRouter 目录给出 Sol 的标价为每百万 token 输入 2 美元、输出 10 美元，上下文长度为 1.1M（以官方与提供商当时页面为准）。开发者文档还提醒：从 GPT-6.2 起，若检测到对话前缀被中途改动、模型降级、终端用户或组织变更，API 可能丢弃 reasoning items；工具调用建议使用 Responses API；迁移时应检查 `reasoning.effort`、不再支持的采样参数，以及 prompt cache 的新选项。官方同时发布了 GPT-6.2 系统卡，并写明这两个模型在准备框架下达到生物/化学能力 High 门槛，Astra 还是首个对外发布、在 AI Self-improvement 上达到 High 门槛的模型，因此伴随着更严格的网络安全相关防护。"
usage: "在 ChatGPT 中：按官方说明，Plus、Pro、Enterprise 与 Edu 用户可在 ChatGPT Work 和 Codex 里选择 GPT-6.2 Astra 或 GPT-6.2 Sol。若你的团队已经开通 Astra for Law，更新后的配置在 ChatGPT 中选择 `gpt-6.2-astra-law`；Enterprise 管理员也可通过 Trusted Access Program 申请。这些是法律配置的入口，不是 Astra / Sol 本体的默认选项。\n\n在 API 中：把 `model` 设为 `gpt-6.2-astra` 或 `gpt-6.2-sol`。官方迁移建议从 `medium` 的推理力度开始；如果旧集成使用 `none` 或 `minimal`，改为 `low`。Responses API 使用 `reasoning.effort`，Chat Completions 使用 `reasoning_effort`。两个模型都支持 Chat Completions，但工具调用需要 Responses API。从 Chat Completions 迁移时省略 `temperature`、`top_p`、`logprobs` 和 `top_logprobs`。为了更好地复用缓存、降低成本与延迟，并在多轮中保留 reasoning，官方建议保持 prompt 前缀不变、把新指令追加在后面。文档还写明两者支持美国与欧盟数据驻留的 Standard、Fast 和 Batch，Ultrafast 仅支持美国数据驻留；经批准的组织可在符合条件的端点上使用 Zero Data Retention。\n\n更完整的评测数字、示例和安全说明见[官方介绍](https://openai.com/index/introducing-gpt-6-2-astra-sol/)、[Using GPT-6.2](https://developers.openai.com/api/docs/guides/latest-model) 以及文中链接的 GPT-6.2 系统卡。第三方路由（例如 OpenRouter 上的 `openai/gpt-6.2-astra`、`openai/gpt-6.2-sol`，以及带 pro 推理模式的 Astra Pro）以各提供商当时的目录与价格为准。"
