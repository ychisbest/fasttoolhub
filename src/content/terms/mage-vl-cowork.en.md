intro: "**Mage-VL-Cowork** is a **4-billion-parameter computer-use agent (CUA)** released by **Microsoft's Mage team** on **October 30, 2026**, with open weights on Hugging Face under **Apache-2.0**. Its tagline is *\"One 4B policy that knows when to click — and when to code.\"*\n\nUnlike agent systems that route between a separate GUI operator and a coding operator, Mage-VL-Cowork is a **single vision-language policy** that sees full-desktop screenshots and, turn by turn, decides whether to emit mouse/keyboard actions or run commands in a persistent shell/Python environment. Microsoft reports **66.0% on OSWorld-Verified** under a 50-step budget — the best result it knows of at the 4B scale, and above larger open agents such as Muse Glimmer-30B (65.9%) and Qwen3.6-27B (63.9%)."
explain: "## Key points\n\n1. **Hybrid action space**: two channels — `computer_use` (11 GUI primitives on normalized coordinates) and `bash` (persistent shell + Python). The policy picks the channel itself; no external router or multi-agent orchestrator.\n2. **Training recipe**: five-stage progressive curriculum (midtraining → GUI SFT → hybrid SFT → online RL) starting from an intermediate Mage-VL checkpoint. Scores climb 45.56% → 55.84% → 66.0% across stages; RL adds +10.16 pp while cutting model calls 13% and output tokens 25%.\n3. **Mage-CUA-Forge**: a workflow-first task synthesizer that generated **293,806 desktop/web tasks across 6,915 skills**, reducing per-task cost by 82.6%.\n4. **Results**: 87.5% on OSWorld OS tasks, 62.7% on multi-app workflows; big gains on ScreenSpot-v2 and OSWorld-G grounding.\n5. **Caveats**: numbers are self-reported with Microsoft's own `MAGEHybridAgent` harness; independent reproductions are pending.\n\n## Why it matters\n\nA 4B model is small enough to run on a single consumer GPU or high-end laptop, so Mage-VL-Cowork pushes capable desktop automation toward **on-device** use — while also raising the usual safety concerns of letting a model run shell commands on a real machine."
