intro: "**ARC / Rayline ARC** 是 Rayline 于 2026 年 11 月 11 日宣布的路由决策模型。创始人 David Valerio Gilmore 在 [宣布帖](https://x.com/davidvgilmore/status/2120583960447029699)（2026-11-11T18:26:29Z）中写道：“Today, we’re introducing ARC by Rayline: the world’s first unified model for routing AI.” 官方把它称为 Adaptive Routing Controller：读取智能体已有的对话，为下一步选择哪个模型、使用多少推理量给出信号。产品页为 [rayline.ai/arc](https://rayline.ai/arc)，站点为 [rayline.ai](https://rayline.ai/)，技术报告为 [ARC: Learned Model Routing for Long-Horizon Agentic Workflows](https://rayline.ai/research/report)，文档为 [docs.rayline.ai/arc](https://docs.rayline.ai/arc)，权重在 [huggingface.co/rayline-ai/ARC-1.0](https://huggingface.co/rayline-ai/ARC-1.0)。\n\n官方说明，ARC 把预测和政策分开：模型预测成功概率和 token 用量，由应用提供价格和策略，再在质量、成本与是否本地执行之间做权衡。更新价格不必在模型和部署配置不变时重新训练这些预测头。模型卡片列出的信号包括：各模型完成任务的预测成功概率、未缓存输入 / 缓存读写 / 输出的用量估计、同一模型内不同推理设置的收益与成本比较、输入中的 PII 检测、请求操作与领域的分类，以及可自定义问题与选项的通用问题头（例如“这条请求是否需要更强的模型？”）。\n\n使用方式上，官方提供两条路径。Generation API：由 Rayline 完成路由并生成回复；Routes API：只返回路由结果，由你在自己的推理端点上执行。Generation API 的预置策略来自同一路由模型：官方在后续帖中写到，**ARC Sage** 更看重高要求任务的质量，**ARC Swift** 更看重日常任务的效率，二者都按模型那样收取固定的输入、输出和缓存价格；**ARC Dynamic** 可自行调节质量/成本权衡，按被选中模型的推理价格计费，官方称加成为 0%。Hugging Face 模型卡片给出效用公式 Utility = V × predicted success − expected cost，其中 Sage 的 V = 4.5，Swift 的 V = 0.1，另有 prefer-local 策略：本地模型达到设定的预测成功阈值就走本地，否则回退。官方称可把 ARC 当作可替换模型，用在 Claude Code、OpenCode、Cursor、OpenClaw 等智能体工具中。\n\n关于模型本身，官方后续帖写到：ARC 专门为多轮对话中的路由而训练，会利用已有对话、可用算力和已缓存上下文，选择下一个模型与推理级别，也可以换模型、调整推理量、继续用当前模型，或在同一次会话里混用云端与本地模型；官方会随新模型发布更新 ARC。路由模型为 8 亿参数，可本地运行，权重以 Apache 2.0 开放，基于 Qwen3.5-0.8B 微调。本轮扫描时，Hugging Face 上的 [rayline-ai/ARC-1.0](https://huggingface.co/rayline-ai/ARC-1.0) 为公开仓库。文档的 Availability 页仍把“模型权重与针对各模型的自托管说明”列为即将提供，引用时请以模型卡片和该页的最新状态为准。\n\n质量与成本数字全部来自官方材料，不是本站独立评测。宣布帖写的是“97.5% of Opus 5.5
