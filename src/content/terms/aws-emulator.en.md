intro: "**AWS Emulator** is the local emulator Amazon Web Services announced as generally available on November 11, 2026, in the official news blog [Test your applications against AWS locally with AWS Emulator](https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/), by Daniel Abib. The post begins: “Today we’re announcing AWS Emulator, a local emulator for Amazon Web Services (AWS) that you run on your machine.” The AWS CLI, the AWS SDKs, and coding agents speak to it over a local HTTPS endpoint using the same AWS APIs they would use in the cloud. The product page is [AWS Emulator](https://aws.amazon.com/products/developer-tools/emulator/), the docs are at [docs.aws.amazon.com/emulator](https://docs.aws.amazon.com/emulator/), and the source repository is [github.com/aws/aws-emulator](https://github.com/aws/aws-emulator).\n\nOfficially, AWS Emulator has no additional service fee; you pay only for AWS resources when you deploy on AWS. You install it from an RPM or Debian package on Linux (the package adds the `aws-emulator` command to `/usr/bin/`), and on macOS and Windows you build a Docker image from the short Dockerfile in the documentation and run it in a container; AWS says it does not publish a ready-made image. When it starts, it serves HTTPS on `127.0.0.1:9297` and writes credentials, a config file, and a certificate to `~/.aws/emulator/9297/`. Access key IDs start with `EMULATOR`, and it rejects requests signed with any other keys. The emulator uses a single account, `000000000000`. It is implemented in Rust. It supports the APIs of AWS services that have an API model in the AWS API models repository on GitHub, so requests and errors have the same shape as on AWS. For tests, there is also an embedded mode (`aws-emulator-embedded` crate, for the AWS SDK for Rust) that you instantiate inside the test process; each embedded instance keeps its own state, so tests can run in parallel. Operations that are not implemented yet return HTTP 501.\n\nOn fidelity, the official blog measures the emulator with fidelity tests: short SDK workflows are first verified against real AWS, and a test passes only if the emulator matches AWS on the status code, body, and exact error code and message of every call, and on the resources and data the workflow creates. Each release publishes how many tests pass per service, as k of n. The set, including tests that do not pass yet, is public in [aws-emulator-evaluation-suite](https://github.com/aws/aws-emulator-evaluation-suite). The blog notes that a score can go down when new tests are added, even while the emulator improves. On how it is built, the blog says AWS Emulator is built and maintained by agents from the AWS API models using Amazon Bedrock AgentCore Runtime Instances, AWS CodePipeline, and AWS CodeCommit. One group of agents looks for gaps by comparing emulator responses against real AWS and by statically comparing code against published Smithy models; another group writes tests, implements the behavior, and reviews the change for correctness, performance, and security before a pipeline run. Because the code is written by agents, an independent security agent reviews changes adversarially while a fix is being made and again in the release pipeline. Amazon’s official news post [How we built the agents that built AWS Emulator](https://www.aboutamazon.com/news/aws/how-autonomous-ai-agents-built-aws-emulator) (Matthew Goldberg, November 11, 2026) says the team has not written or reviewed any of the code, that the source is released under Creative Commons CC0, and that issues live in `issues/things-that-now-work` and `issues/things-that-do-not-work`. Amazon CTO Werner Vogels [posted](https://x.com/Werner/status/2120577888844148891) at 2026-11-11T18:02:21Z that “AWS Emulator, launched today and written and tested entirely by agents, gives you that kind of environment for more than 200 AWS services,” and linked to the guest post at https://www.allthingsdistributed.com/2026/11/aws-emulator-and-the-engineers-job-when-agents-write-the-code.html .\n\nOn limits, the official blog says the emulator does not evaluate IAM policies and resource-based policies the way AWS does, so a request that AWS denies might succeed in the emulator; each emulator acts as a single account, with no cross-account or cross-Region behavior; how closely it matches AWS varies by service and feature; you should not use it to test whether your application is secure, and you should keep real credentials out of test-job environments. By default it also sends anonymous usage and error data, which you can turn off.\n\nKey points:\n\n- Official blog: https://aws.amazon.com/blogs/aws/test-your-applications-against-aws-locally-with-aws-emulator/ ; product page: https://aws.amazon.com/products/developer-tools/emulator/ ; docs: https://docs.aws.amazon.com/emulator/ ; source: https://github.com/aws/aws-emulator ;\n- Werner Vogels post: https://x.com/Werner/status/2120577888844148891 (2026-11-11T18:02:21Z); Amazon news: https://www.aboutamazon.com/news/aws/how-autonomous-ai-agents-built-aws-emulator ;\n- This is **a specific AWS developer-tool name**. Do not confuse it with LocalStack, or with a hosted service in a real AWS Region."
