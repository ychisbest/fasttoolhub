intro: "**Stitch AI** 是银行基础设施公司 [Stitch](https://www.stitch.co/ai) 在 2026 年 11 月 17 日推出的代理式 AI 产品名。官方新闻稿《Stitch casts Patrick J. Adams to launch Stitch AI, agentic AI for banks》（[stitch.co/press/...](https://www.stitch.co/press/stitch-casts-patrick-j-adams-to-launch-stitch-ai-agentic-ai-for-banks)）在利雅得发布，CEO 为 Mohamed Oueida。产品说明集中在 [stitch.co/ai](https://www.stitch.co/ai)。\n\n官方把它写成**做进 Stitch 操作系统和账本里的 AI**，而不是外挂在银行系统旁边的通用助手。产品页把能力分成三块：一个用自然语言查询数据、配置产品和发起变更的 copilot；一套用于入职、授信、反欺诈、催收和客服等场景的预置 agent；以及一个带权限、审批、护栏和审计的 Agent Harness，用来构建自定义 agent。\n\n名称上必须用 **Stitch AI**，不要简写成 Stitch。Stitch 本身是这家公司的银行 OS / ledger 产品；Google 也有同名的 UI 相关产品，开源圈里还有 stitch-skills 等无关仓库。本条只收录 11 月 17 日这个面向银行的新名字。"
explain: "官方产品页强调的约束是银行业已有的规则、环境和账本。Copilot 可以用自然语言要数据、建立贷款产品、改流程或改定价，但“every change waits for approval”。预置 agent 覆盖 credit decisioning、collections outreach、anti-fraud、customer service、transaction monitoring、loan portfolio analysis、payment failure analysis 等，官方展示可以一步加到现有工作流里。\n\n自定义 agent 则在 Agent Studio / Agent Harness 里完成：给它一项工作，选择可以使用的 Stitch 服务和系统，在真实数据上测试后再发布。官方举例包括催收跟进 agent，以及规则引擎拦截“批量导出个人数据”或“把客户数据发到 Gmail”这类动作，并留下审计日志。官方还写明：每个 agent 有自己的身份、范围权限、硬限制、maker-checker 和完整审计；敏感数据在模型看到之前会被遮蔽；可以在境内或私有云运行，并更换开源、闭源或定制模型而不必重做整套系统。\n\n这些都是 Stitch 作为银行 OS 供应商给出的产品主张，实施细节、合规边界和上线范围以官方说明与合同为准。不要把它理解成可以脱离账本、在任意 SaaS 里任意行动的通用 agent 平台。"
