intro: "**Exo** is an **agent harness architecture for runtime self-improvement**: it collapses the optimization loop into task execution so an agent can inspect and **edit its own harness policy** while working. Paper: https://arxiv.org/abs/2611.00463 (arXiv 2611.00463); code: https://github.com/exoharness/exo . Authors include researchers affiliated with UC Berkeley, Andreessen Horowitz, and Braintrust.\n\nDesign (exokernel-inspired) splits the system into:\n\n- An **evolvable policy layer (executor)**: tool selection, context assembly/compaction, memory/skill retrieval, and when/how to improve further—all editable code;\n- A **protected mechanism layer**: append-only execution history, versioned artifacts, credentials and sandbox APIs, plus an independent **guardian** that gates policy activation and enables rollbacks.\n\nReported results (paper): on long open-world game objectives, model cost drops about **12–53%** vs Codex/Pi in standalone runs and **45–82%** in transfer runs; vs the same starting policy without policy editing, held-out cost falls on AppWorld/SREGym with comparable correctness. Model weights stay fixed; improvements are harness code changes."
explain: "## Problem\n\nHarness policies are usually hand-written or tuned in an external loop that repeatedly runs candidates on benchmarks. New domains often lack benchmarks; long tasks make evaluation expensive; and fixed policies cannot absorb runtime lessons. Exo lets the running agent revise both task behavior and its improvement strategy with the same code-editing tools it already uses.\n\n## Safety mechanisms\n\n- **Storage contract**: append-only history so self-edits cannot erase evidence;\n- **Replacement contract**: candidates activate only if the guardian accepts them; independent rollback;\n- Adaptations appear as inspectable code diffs.\n\n## Limits\n\n- Fate-sharing risk if a bad edit breaks the agent—hence the protected core;\n- Specialization has upfront cost and may not pay off on one-shot, low-reuse work (paper example);\n- Numbers are from the paper's setups/models—validate in your environment."
usage: "## Who it's for\n\n- Teams researching or shipping self-improving agent harnesses;\n- Long-horizon workloads where reusable tools and context policies amortize learning.\n\n## Getting started\n\n1.
