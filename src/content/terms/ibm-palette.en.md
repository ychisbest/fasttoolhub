intro: "**IBM Palette** is a research system published by **IBM Research** on **2026-11-03**. Its bet: a **small, self-hostable open-weight model** can build slide decks in a company's **own design language** (here, the IBM Design Language) and compete with frontier tools.\n\nPalette fine-tunes a **20B open-weight base** (the repo refers to `gpt-oss-20b-palette-lora`) with a **single LoRA adapter** that serves two roles:\n\n- **Designer** – reads the plan and writes a structured JSON brief: palette, type system, and per-slide layout, exact content and design rationale;\n- **Coder** – takes one slide spec and writes the **pptxgenjs** JavaScript that draws it.\n\nA **check-and-repair harness** renders every slide, flags overlap/clipping/overflow, sends flagged slides to an editor model, and keeps a rewrite **only if the checker confirms it improved**. Output is a downloadable **.pptx** plus PDF preview."
explain: "## What problem it solves\n\nEnterprise decks suffer from two issues: frontier models produce a recognizable \"AI house style\" that ignores brand guidelines, and confidential content shouldn't leave the company. Palette uses an **owned, self-hostable open-weight model** to address both.\n\n## Key techniques\n\n- **Role split**: the designer fixes the story and layout first, then the coder draws each slide; since each slide's context is fixed before coding, coder calls run **in parallel**, making the coding stage about **6–7× faster**.\n- **Synthetic data**: a large open teacher generated ~**1,000 decks / 10,000 slides**, each choice paired with counterfactual reasoning (e.g., why a chart instead of a table).\n- **Faithfulness first**: IBM says the hardest problem was invented facts; changing the teacher's reference decks helped more than prompt rules.\n- **Check-and-repair**: across 131 PresentBench decks the harness added **3.5 points** on average.\n\n## Results and caveats\n\nOn PresentBench Palette ranks **first on Economics and Education**, third on Talk, and second on the three-domain mean (**59.7** vs NotebookLM 60.8), ahead of Manus 1.6 and others. Caveats: results are self-reported; PresentBench measures general deck quality, not brand-language adherence; weight availability is not yet clearly stated."
