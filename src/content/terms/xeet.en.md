The post says: “A hermetic, pixel-perfect X post renderer in safe Rust / wasm. Zero browser, network, filesystem, system fonts. Renders a post to PNG in ~1ms (and 0.4 ms for @jack's \\\"setting up my twttr\\\").”\n\nThe official site describes the same product: hand it a post, or just an `x.com` link, and you get back a Retina PNG with the same line breaks, emoji, fallback fonts, and “Show more” placement. The docs emphasize that most preview tools boot headless Chromium and take a screenshot; xeet instead reimplements the parts a post actually depends on — X's client rules, Blink and HarfBuzz text layout, the flexbox geometry around the text, and Skia-style anti-aliasing — and marks the core `#![forbid(unsafe_code)]`. It ships as one native binary and one WebAssembly core, plus font packs the host registers on first use. Official figures for a text post at 390 px and 3× are about 2.8 ms p50, or about 4.5 ms with four media placeholders. Rendering needs no network, filesystem, clock, or system fonts, and the native and WASM builds produce the same bytes.\n\nSource is at [rauchg/xeet](https://github.com/rauchg/xeet) under Apache-2.0; GitHub lists the repository as created at 2026-11-15T18:07:57Z. Documented installs include `npm i @xeet/core`, `npm i -g @xeet/cli`, and `cargo install --git https://github.com/rauchg/xeet xeet-cli`. A CLI example is `xeet render post.json --width 390 --theme dark --dpr 3 -o post.png`; `xeet resolve` can turn an `x.com` URL into a post and then render it. npm published `@xeet/core` and `@xeet/cli` 0.1.0 around 2026-11-15T21:28Z.
