intro: "**Perplexity Time Machine** is a retrieval feature Perplexity launched on 25 November 2026. It adds a date cutoff to the Search API and the Context API so an agent sees the web as it was, not the live web that already knows how the story ended. The official developer account [@perplexitydevs](https://x.com/perplexitydevs/status/2125676416834605488) introduced it at 19:42 UTC that day (03:42 on 26 November, Beijing time). The post is [Freeze the web with Perplexity Time Machine](https://www.perplexity.ai/hub/blog/freeze-the-web-with-perplexity-time-machine), dated 25 November 2026, with docs at [Time Machine](https://docs.perplexity.ai/docs/search/time-machine).\n\nThe company says that adding `snapshot_as_of` limits both search and full-page reading to copies Perplexity saved at or before that timestamp, currently up to 365 days back. Its example is straightforward: ask today what was known before an election or an earnings call, and the live web often already reports the outcome; Time Machine lets a model work only with what was visible then, so research and forecasting can be scored more fairly. This site already has a page for [Epochal Time Portal](/en/terms/epochal-time-portal/), a different lab’s time-gated web sandbox. This entry covers only the feature Perplexity added to its own Search and Context APIs.\n"
explain: "## What the company claims\n\nThe mechanism and limits below come from the 25 November [official blog](https://www.perplexity.ai/hub/blog/freeze-the-web-with-perplexity-time-machine) and the [Time Machine docs](https://docs.perplexity.ai/docs/search/time-machine). They are the vendor’s description.\n\nPerplexity says that each time it crawls a page for its web index, it saves a copy together with the time it was saved, so each URL builds up a version history. With `snapshot_as_of` set:\n\n- Search only considers pages that were published, or first crawled by Perplexity, by the cutoff.\n- The cutoff is compared with the time a copy was saved, not with a date shown on the page.\n- Each result is swapped for that URL’s latest copy saved at or before the cutoff; the title, date, and snippet come from that older copy, so a later edit that announces the outcome cannot rank for it.\n- The response has the same shape as a normal search, except that `last_updated` is omitted.\n\nThe blog’s typical workflow is to search first with the cutoff, then send the result URLs to the Context API with the **same** `snapshot_as_of`, so the second step does not fall back to the live web. The docs also note that a page which cannot be shown as of the cutoff is omitted, so a search can return fewer than `max_results` results, or none. The Context API requires at least one URL, and the official examples call it only when the search returns results.\n\n### Official use cases\n\nThe blog groups the feature around workflows where hindsight would invalidate the result: reinforcement learning on past questions, replaying points before resolution on prediction markets or in finance backtests, pinning a benchmark to one `snapshot_as_of` so score changes reflect the model rather than new web content, replaying a past agent session to tell model error from what the web said that day, and comparing the same URL at two timestamps for pricing pages, terms, or changelogs. As an example, the company says it used RL to train GLM-5.3 Flash to forecast real 2026 political events listed on Polymarket, with Time Machine allowing the model to search news and polls available by that day, but not later coverage announcing the winner.\n\n### Parameter limits (from the docs)\n\nThe docs require `snapshot_as_of` to be an RFC 3339 time with a time zone (for example `2026-11-01T00:00:00Z` or `2026-11-01T09:30:00+02:00`). It cannot be in the future, and cannot be more than 365 days ago. You may also send `search_domain_filter` and `search_language_filter`. It **cannot** be combined with `search_recency_filter`, the date filters, or People Search (`search_type: \"people\"`). In the SDKs, the docs say to use a timezone-aware `datetime` in Python and a `Date` in TypeScript.\n"
usage: "## How to try it\n\nYou need a Perplexity API key and must pass `snapshot_as_of` on Search and Context requests. The example below is adapted from the [official docs](https://docs.perplexity.ai/docs/search/time-machine) and searches python.org as the web was 30 days ago.\n\nInstall the official library, set `PERPLEXITY_API_KEY`, then:\n\n```python\nfrom datetime import datetime, timedelta, timezone\nfrom perplexity import Perplexity\n\nclient = Perplexity()\nsnapshot_as_of = datetime.now(timezone.utc) - timedelta(days=30)\n\nsearch = client.search.create(\n    query=\"latest stable Python release\",\n    snapshot_as_of=snapshot_as_of,\n    search_domain_filter=[\"python.org\"],\n    max_results=5,\n)\n\nfor result in search.results:\n    print(f\"{result.title}: {result.url}\")\n```\n\nTo read the full text of those pages at the same cutoff, send the result URLs to the Context API with the same `snapshot_as_of` (the docs call this only when the search returns results):\n\n```python\nif search.results:\n    response = client.context.create(\n        urls=[result.url for result in search.results],\n        snapshot_as_of=snapshot_as_of,\n    )\n    for result in response.results:\n        if result.status.type == \"ok\":\n            print(result.url, result.metadata.fetched_at)\n```\n\nYou can also POST JSON with `snapshot_as_of` to `https://api.perplexity.ai/search`. The docs note that the cURL sample uses a fixed timestamp, so replace it with a time from the last 365 days.\n\n### Links\n\n- Official blog: [Freeze the web with Perplexity Time Machine](https://www.perplexity.ai/hub/blog/freeze-the-web-with-perplexity-time-machine) (25 November 2026)\n- Docs: [Time Machine](https://docs.perplexity.ai/docs/search/time-machine)\n- Official post: https://x.com/perplexitydevs/status/2125676416834605488\n"
