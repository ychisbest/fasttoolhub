intro: "**Pax** (package name **pydantic-ai-pax**) is Pydantic’s official terminal coding agent, released on 25 November 2026 and built on the Pydantic AI Harness SDK. The official account [@pydantic](https://x.com/pydantic/status/2125684732532777140) announced it at 20:15 UTC that day (04:15 on 26 November, Beijing time): “We just released Pax, the official Pydantic AI coding agent for your terminal.” The accompanying post is [Introducing Pax and the Pydantic AI Harness beta, on the road to 1.0](https://pydantic.dev/articles/pax-harness-beta), by Michael Pfaffenberger, Douwe Maan, Aditya Vardhan, and David Sanchez, dated 25 November 2026, with docs at [Pax](https://pydantic.dev/docs/ai/pax/).\n\nThe blog describes Pax as the terminal UI in front of the `Coder()` capability: a daily-driver coding agent and a showcase of the Harness SDK. As everything in the Harness is a capability, the company says, everything in Pax is a plugin—including the coding agent itself, sandboxes, MCP, Logfire tracing, and your own plugins. You can also point `pax --agent` at any Pydantic AI `Agent` in your repo and ship that same object in a service.\n"
explain: "## What the company claims\n\nThe account below comes from the 25 November [official blog](https://pydantic.dev/articles/pax-harness-beta) and the launch tweet. It is the vendor’s description.\n\nThe post separates three layers. **Pydantic AI** is the agent framework (the loop, models from major providers, tools, and structured output). **Pydantic AI Harness** is the production capability library on top of it; the company says it now has more than 100 composable capabilities, including durable execution that survives crashes (for agents built on the SDK; **not in Pax yet**), one workspace API across your machine and a dozen sandboxes, native computer use on each provider, model fallback that also catches refusals, code mode, plus file and shell tools, guardrails, memory, sub-agents, context management, and Agent Skills. One of those capabilities is `Coder()`: what the industry calls a coding harness is, in Pydantic AI, a bundle of capabilities that turns any agent into a coding agent. **Pax** is the terminal UI in front of `Coder()`.\n\nThe company also says Harness is about a month from a 1.0 release, after which it will follow the same version policy as Pydantic AI, so this is the window to stress-test it before the public API is set.\n\n### Plugins, your own agent, and sandboxes\n\nA Pax plugin, the blog says, is a capability one layer up: tools and hooks for the agent, plus terminal pieces such as `/commands`, status-bar items, and logins. Even the coding agent is a plugin. In `/plugins` you can toggle `coder`, `sandbox`, `observability` (Pydantic Logfire tracing), `mcp`, and the rest. `/plugins disable coder` leaves a clean chat client with no file or shell tools. Any Pydantic AI capability can be used as a plugin by import path, and the company says Pax can write new plugins for itself when you ask.\n\n`--agent` (or `-a`) **replaces** the default agent with any Pydantic AI `Agent` from your codebase. The official example defines a reviewer with a guideline-lookup tool, then runs `pax --agent my_agents:reviewer`. Pax loads no default plugins and uses that agent’s own model, tools, and instructions, while still providing the terminal flags `--resume`, `--worktree`, `-p`, and `-m`.\n\nFile and shell tools talk to a workspace, so the same tool code can run on your machine or in a cloud sandbox. In Pax you can switch before the first prompt with `/sandbox e2b` (the post also lists `boxd`, `daytona`, `opensandbox`, `modal`, `render`, `sprites`, and `kubernetes`), or `/sandbox local smol` / `/sandbox local boxlite` for a local micro-VM. The company says Pax syncs your branch and uncommitted diff, runs edits, builds, and `!` commands inside the sandbox, and reconnects on `/resume`. On proxy-enabled providers, it says your GitHub token never enters the sandbox; an egress proxy injects it on outbound GitHub requests.\n\n### Vendor benchmark notes and what’s next\n\nThe blog says that in single runs of Harness-Bench SWE81, Pax had the highest average score of the four harnesses that ran all eight models, “narrowly”; it cost less than half of what Codex did on GPT-6.2 Sol, and about the same as Claude Code on Claude Opus 5.5. Those figures are the company’s own, not a third-party reproduction.\n\nOn computer use, the post shows how `ComputerUse()` can give a Harness agent a desktop, and states that **in Pax, computer use is coming in the next release as `/computer-use`**: turn it on in a new conversation before `/sandbox PROVIDER`, and the desktop needs `/permissions full`.\n"
