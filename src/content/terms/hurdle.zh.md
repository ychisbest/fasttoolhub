explain: "## 官方怎么介绍它\n\n以下内容来自 11 月 25 日的 [官方博文](https://www.together.ai/blog/introducing-hurdle-run-agent-evals-on-your-api-skills-and-docs) 和官方介绍帖，属于厂商说明。\n\nHurdle 把一项任务写成开发者会交给智能体的提示词，再在你指定的智能体、模型和条件下反复运行，记录全过程并打分。打分方式可以单独使用，也可以组合：\n\n- **代码检查（code checks）**：对运行结果做断言，例如智能体必须发出哪些 API 请求、应生成哪些文件或数据。\n- **护栏（guards）**：在运行过程中拦截不允许的操作（例如创建付费集群）；一旦尝试，该次运行计为失败。官博写明，请求级检查和护栏只在沙箱运行里可用。\n- **评判模型（judge）**：用大模型按你用自然语言写的评分细则，审阅整场会话并判定是否通过。\n\n同一任务还可以放在不同 **条件（conditions）** 下对比，例如一组智能体安装了你的 MCP 或 skill，另一组没有，从而看这些配套是否真的有帮助。套件会按你指定的智能体/模型组合跑完全部任务，并支持多次重复，得到总体通过率。\n\n官博用“找出最便宜的 GPU 集群、打印预留命令、但不要真正下单”作为示例任务，并用 `defineChecks`、`defineGuard` 和 `defineSuite` 分别声明请求检查、禁止创建集群的护栏，以及任务、模型、条件和重复次数。套件里可把 `verdict` 设为 `hybrid`，要求代码检查和评判模型同时通过。\n\n### 本地运行与沙箱运行\n\n官博区分了两种执行环境。**本地运行**适合你信任的快速测试：Hurdle 在本机临时工作区启动 `claude` 或 `codex` CLI，交给任务提示和文件并录制会话；每次都以干净配置开始，不沿用你日常的 Claude Code 或 Codex 设置。限制是：Hurdle 看不到也拦不住智能体的 API 请求，因此不能使用护栏或请求检查；而且智能体以你的身份运行，能读本地文件、使用真实密钥。\n\n**沙箱运行**面向正式评测。官博称会通过 Together Sandbox API 为每次运行拉起隔离环境，智能体可在其中执行代码、安装依赖并调用 API，但不能访问你的本机。启动时，Hurdle 会在本地打开名为 Guardian 的代理，再经 WebSocket 连接到 Together，由对方为该次运行准备新的沙箱。\n\n这些是厂商对自己产品的说明，不是第三方复现。\n"
usage: "## 现在怎么用\n\n官博给出的起步与查看结果方式是：\n\n```bash\nnpx hurdle init\nnpx hurdle run --view\nnpx hurdle view\n```\n\n`npx hurdle run` 会按套件执行评测；加上 `--view` 会在结束后打开结果查看器。官博称结果保存在项目目录的 `.hurdle/` 下，之后可用 `npx hurdle view` 再次打开。终端里会随每次运行结束标出通过、失败或跳过。查看器顶部给出通过率、平均时长和每次运行的平均费用，并按任务与条件列出明细；点进单次运行可看到完整会话、工具调用、API 请求，以及各项检查和评判模型的结论。\n\n更完整的套件写法、检查与护栏示例见官博中的 “Example task” 和 “The eval suite” 小节，以及 [GitHub 仓库](https://github.com/togethercomputer/hurdle)。\n\n### 相关链接\n\n- 官博：[Introducing Hurdle: Run agent evals on your API, skills, and docs](https://www.together.ai/blog/introducing-hurdle-run-agent-evals-on-your-api-skills-and-docs)（2026-11-25）\n- 代码：[togethercomputer/hurdle](https://github.com/togethercomputer/hurdle)\n- 官方介绍帖：https://x.com/togethercompute/status/2125709140425363612\n"
