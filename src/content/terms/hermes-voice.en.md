Repo: https://github.com/majorminorlabs/hermes-voice (created **2026-11-05**; radar ~**224★**, GitHub API later reported **225**).\n\nWhat the repo adds:\n\n- `custom_components/hermes_voice` — Home Assistant **conversation agent** that forwards each turn to a Hermes profile with a stable `X-Hermes-Session-Id`, streams replies for earlier speech, and cleans text for TTS;\n- `skill/hermes-voice-setup` — a Hermes skill so your agent can prepare a voice profile and install/configure HA + hermes_voice;\n- `wakeword/` — training pipeline plus a bundled **“hey hermes”** microWakeWord model;\n- Docs for a dedicated voice profile (SOUL.md, tools, thinking effort, separate provider).\n\nPipeline sketch: Echo (wake word / mic / speaker) → HA Assist (STT → hermes_voice conversation → TTS) → Hermes Agent profile API (`/v1/chat/completions`)."
explain: "## Problem\n\nHermes Agent already has profiles, memory, and tools, but everyday voice satellites speak Home Assistant’s Assist language. Hermes Voice is the missing conversation-agent piece—not a full smart-home stack rewrite.\n\n## Design choices\n\n- **One HA entry per Hermes profile**, selected by gateway URL (standalone port or multiplexed `/p/<profile>/v1`);\n- Session modes: `per_conversation` (default) or `per_device` with idle reset; Hermes keeps history via the session header;\n- Adds a short “answer briefly, for speech” system message (configurable); personality stays the profile’s SOUL.md / memory;\n- **v0.1 does not grant Home Assistant device control** via this integration—give the profile HA’s MCP server if you need that;\n- Documented latency ~**3.5 s** for plain turns in testing (mostly model time); streaming can speak a working phrase while tools run.\n\n## Limits\n\n- Device flashing (echo-dot-assist) can brick hardware—follow device recovery notes;\n- Shared provider logins share rate limits; memory is per profile, not per speaker;\n- Wake-word model tested on limited hardware; requires Home Assistant **2026.10+** (version tested)."
