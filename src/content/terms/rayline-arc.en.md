intro: "**ARC / Rayline ARC** is a routing decision model announced by Rayline on November 11, 2026. Founder David Valerio Gilmore wrote in the [announcement post](https://x.com/davidvgilmore/status/2120583960447029699) at 2026-11-11T18:26:29Z: “Today, we’re introducing ARC by Rayline: the world’s first unified model for routing AI.” Officially it is also called the Adaptive Routing Controller: it reads an agent’s conversation so far and produces signals for choosing a model and a reasoning level for the next step. The product page is [rayline.ai/arc](https://rayline.ai/arc), the site is [rayline.ai](https://rayline.ai/), the technical report is [ARC: Learned Model Routing for Long-Horizon Agentic Workflows](https://rayline.ai/research/report), the docs are at [docs.rayline.ai/arc](https://docs.rayline.ai/arc), and the weights are at [huggingface.co/rayline-ai/ARC-1.0](https://huggingface.co/rayline-ai/ARC-1.0).\n\nOfficially, ARC separates predictions from policy. It predicts success and token usage; the application supplies prices and decides how to balance quality, cost, and local execution. Updating prices does not require retraining those predictors when the model and serving configuration stay fixed. The model card lists signals for: predicted probability that an eligible model will complete a task; estimates of uncached input, cache reads, cache writes, and output; the expected benefit and cost of supported reasoning settings within a model; PII detection in the supplied input; classification of requested operations and domains; and a general-purpose question head that takes a question and answer options (for example, “Does this request need a stronger model?”).\n\nThere are two official ways to use it. The Generation API lets Rayline handle routing and generation. The Routes API returns a routing decision for you to run on your own endpoints. The Generation API presets are configurations of the same router. In a follow-up post, the company introduced **ARC Sage**, which puts more weight on quality for demanding work, and **ARC Swift**, which focuses on efficiency for everyday tasks; both are priced like models, with fixed input, output, and cache rates. **ARC Dynamic** lets you tune the cost/quality tradeoff and, officially, you pay the selected model’s inference rates with 0% markup. The Hugging Face model card gives the utility rule Utility = V × predicted success − expected cost, with V = 4.5 for Sage and V = 0.1 for Swift, plus a prefer-local policy that uses an eligible local model when it clears a chosen predicted-success threshold and otherwise falls back. Officially, you can use ARC as a drop-in model in Claude Code, OpenCode, Cursor, OpenClaw, and other agent harnesses.\n\nOn the model itself, a follow-up post says ARC was trained for routing across multi-turn conversations. It uses the conversation so far, available compute, and cached context to choose the next model and reasoning level; it can switch models, adjust reasoning, stay with the current model, or mix cloud and local models in one session. Officially, Rayline updates ARC as new models arrive. The router is an 800-million-parameter model that can run locally, with open weights under Apache 2.0, fine-tuned from Qwen3.5-0.8B. At the time of this scan, [rayline-ai/ARC-1.0](https://huggingface.co/rayline-ai/ARC-1.0) was a public Hugging Face repository. The docs Availability page still listed “ARC weights and model-specific self-hosting instructions” as coming soon, so check that page and the model card for the current status before you rely on self-hosting details.\n\nQuality and cost figures are all from official materials, not independent tests by this site. The announcement post states “97.5% of Opus 5.5 quality” and “Up to 1/10th of the cost.” The technical report and model card say that, in the paper’s hybrid edge–cloud configuration, across six benchmarks, it retains **97.5%** of Opus 5.5 quality at **92.9%** lower cost, using DeepSeek V4.1 Flash and a multiple-DGX-Spark setup with a 0.85 prefer-local threshold. The homepage also shows another comparison: 97.4% quality retained, ARC at 14.3% of cost, and ARC + local at 7.1%. The model card also reports official per-benchmark examples: on DeepSWE, Opus 5.5 at 69.9% success, ARC Sage at 68.7%, at 7% of baseline cost; on Terminal-Bench 2.1, Opus 5.5 at 91.0%, ARC Sage at 92.4%, at 58% of baseline cost.\n\nKey points:\n\n- Product: https://rayline.ai/arc ; site: https://rayline.ai/ ; technical report: https://rayline.ai/research/report ; docs: https://docs.rayline.ai/arc ; weights: https://huggingface.co/rayline-ai/ARC-1.0 ;\n- Announcement: https://x.com/davidvgilmore/status/2120583960447029699 (2026-11-11T18:26:29Z); follow-up: https://x.com/davidvgilmore/status/2120583975081255196 ;\n- This is **a specific Rayline product name (ARC / Adaptive Routing Controller)**. Do not describe it as a new version of a frontier lab model, or confuse it with other projects that also use the name ARC."
