intro: "**Frostbite** 是 Architect Labs 在 2026 年 11 月 18 日介绍的通用 CPU 和新指令集。官方研究博文 [Introducing Frostbite: A new CPU architecture discovered, designed, and verified end-to-end by AI](https://architectlabs.com/blog/frostbite)（标注 Research，November 18, 2026）写到：“Today, we're introducing Frostbite, a general-purpose CPU with a new instruction set built from the ground up.” 公司官网为 [architectlabs.com](https://architectlabs.com/)。\n\n官方把这次发布写成对前一篇 **Redwood**（由 AI 在约两周内设计、验证并部署的推理加速器）的延伸：这次要回答的是，AI 系统能否在更自由的联合设计下，发现并做出性能明显优于既有人工设计的新型硬件。Frostbite 的计算模型建立在 interaction nets（交互网）上：官方概括为每一步都是局部的、依赖关系是显式的、每个值只有一个所有者。程序用类似 Rust 的语言 [Vine](https://vine.dev) 编写，再编译到名为 Ivy 的中间表示。\n\n本条记录的是这次新出现的 CPU 名 **Frostbite**。不要把它和 Electronic Arts 的 Frostbite 游戏引擎，或 Architect Labs 此前已经公开的加速器项目 Redwood 混为一个词条。文中还出现了该公司自研的形式化规格语言 **ASL** 和系统模型 **Arcmodel**；官方写到会另文介绍 ASL，本轮不把它们单独建为产品词条。"
explain: "官方称，设计过程没有预设既有 CPU 架构，而是由多组 agent swarm 完成架构探索、形式化合约与系统建模、RTL 与功耗对齐，再一起迭代。探索阶段先按程序暴露工作的方式（大量独立片段、多轮并行、长串行链、数据相关分支、递归）构造搜索集和留出评估集；后来又向留出集加入卡尔曼滤波、PCA、有限元分析、LU 求解和 LZ4 解压等五项更实际的负载。系统随后用自研规格语言 ASL 写出名为 Arcmodel 的系统模型。官方称 ASL 可在 RTL、系统模型、UVM、SVA 等之间做可机器检查的翻译与精化，功耗与性能估计误差约在 1–5%，运行速度大约比 RTL 仿真快 200 倍，并原生翻译到 Lean 做定理证明；文末写到 Frostbite 的 ASL 最终降到了 80 多万行 Lean。Arcmodel 最初不具备物理感知，与时序收敛、可综合 RTL 的偏差在最坏情况下几乎达到 250%，因此有一条自动流程根据 RTL 功耗热点回标形式化规格中的计数器，直到两者误差落入 1–5%。之后合约、Arcmodel、RTL 和功耗一起前进；官方称四轮搜索加最后一轮消融共尝试 58 个想法、保留 37 个。\n\n结果一节写到：Frostbite 在 7 nm 工艺上综合，综合时序达到 800 MHz，最终 GDS 为 500 MHz。一个 Frostbite quad（2×2 个 tile）加上四个 L3 节点的面积是 0.792 mm²。对比对象被称作 TCPU（“Traditional CPU”）：同一工艺下面积 0.895 mm² 的现代、已硅验证超标量 CPU 的单核，官方称它是双发射、顺序处理器，并加注因法律原因不能披露具体型号。面积相近的“单核”对比中，官方给出全部工作负载平均 8.77 倍的性能面积比；25 项工作负载（10 项搜索集加 15 项留出集）上，性能功耗的几何平均是 TCPU 的 4.59 倍，其中搜索集 6.02 倍、留出集 3.83 倍。官方也写到，架构在高度可并行任务上优势最大，但在分支和动态代码上也优于 TCPU。这些数字均为公司表述，而且是预硅结果，不是本雷达的独立复测。\n\n后续计划包括：提供可在 FPGA 上运行程序的软件 playground、编写初步操作系统、继续提升性能功耗并在更大工作负载集合上对比更多 CPU，以及发布 Frostbite 的 RTL 和指令集。"
