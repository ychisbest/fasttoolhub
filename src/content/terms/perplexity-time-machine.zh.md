intro: "**Perplexity Time Machine** 是 Perplexity 于 2026 年 11 月 25 日正式推出的检索功能：给 Search API 和 Context API 加上时间截止点，让智能体看到的是“那一天的网页”，而不是事后已经写好结局的活网。官方开发者账号 [@perplexitydevs](https://x.com/perplexitydevs/status/2125676416834605488) 于 11 月 25 日 19:42 UTC（北京时间 11 月 26 日 03:42）发帖介绍，官博为 [Freeze the web with Perplexity Time Machine](https://www.perplexity.ai/hub/blog/freeze-the-web-with-perplexity-time-machine)，日期标注 Nov 25, 2026；配套文档见 [Time Machine](https://docs.perplexity.ai/docs/search/time-machine)。\n\n官博写道：在请求里加上 `snapshot_as_of`，搜索和全文阅读就只会使用 Perplexity 在该时间点或更早保存的页面副本，回溯窗口目前最长 365 天。官方举例：若今天再问“选举或财报发布前人们知道什么”，活网往往已经带上结果；Time Machine 让模型只能依据当时可见的材料作答，从而更公平地评估研究和预测能力。本站已有词条 [Epochal Time Portal](/terms/epochal-time-portal/)，那是另一家实验室的时点互联网沙箱；本页只记录 Perplexity 在自家 Search / Context API 上推出的这项同名功能。\n"
explain: "## 官方怎么介绍它\n\n以下机制与限制均来自 11 月 25 日的 [官方博客](https://www.perplexity.ai/hub/blog/freeze-the-web-with-perplexity-time-machine) 和 [Time Machine 文档](https://docs.perplexity.ai/docs/search/time-machine)，属于厂商说明。\n\n官方称：Perplexity 每次为网页索引抓取页面时，会连同保存时间一起留下副本；同一个 URL 会逐渐积累版本历史。加上 `snapshot_as_of` 后：\n\n- 搜索只考虑在截止点之前已发布、或已被 Perplexity 首次抓到的页面。\n- 截止点比对的是**副本的保存时间**，不是页面上显示的日期。\n- 每条结果会换成该截止点当时最新的那份副本，标题、日期和摘要都来自这份旧副本；后来被改写成“已有结局”的版本不会因此靠前。\n- 响应格式与普通搜索相同，但会省略 `last_updated`。\n\n官博建议的典型流程是：先用 Search API 按截止点检索，再用**同一个** `snapshot_as_of` 把结果 URL 交给 Context API 读全文，避免第二步又回到活网。文档还写到：若某页在截止点无法展示，结果可能少于 `max_results`，甚至为空；Context API 至少需要一个 URL，因此示例只在搜索有结果时才调用它。\n\n### 官方列出的用途\n\n官博把适用场景概括为“事后诸葛亮会让结果失效”的工作流，包括：用过去的问题做强化学习、在预测市场或财经回测里回放决议前的时点、把基准钉在同一个 `snapshot_as_of` 上以便比较模型而非网页更新、重放过去的智能体会话以区分模型错误和当时网页内容，以及对比同一 URL 在两个时间点的定价页、条款或更新日志。文中举例：他们曾用强化学习训练 GLM-5.3 Flash，在 Time Machine 条件下预测 2026 年 Polymarket 上的真实政治事件——模型只能搜索截止日当时的新闻和民调，而不能看到后来公布胜选结果的报道。\n\n### 参数限制（以文档为准）\n\n文档规定 `snapshot_as_of` 必须是带时区的 RFC 3339 时间（例如 `2026-11-01T00:00:00Z` 或 `2026-11-01T09:30:00+02:00`），不能是未来，也不能早于 365 天前。可以一并使用 `search_domain_filter` 和 `search_language_filter`；**不能**与 `search_recency_filter`、日期过滤器，以及 People Search（`search_type: \"people\"`）同时使用。文档还写到：在 SDK 里，Python 使用带时区的 `datetime`，TypeScript 使用 `Date`。\n"
usage: "## 现在怎么用\n\n需要 Perplexity API 密钥，并在 Search / Context 请求中传入 `snapshot_as_of`。下面的例子改写自 [官方文档](https://docs.perplexity.ai/docs/search/time-machine)，用于按 30 天前的网页索引检索 python.org。\n\n先安装官方库并设置 `PERPLEXITY_API_KEY`，然后：\n\n```python\nfrom datetime import datetime, timedelta, timezone\nfrom perplexity import Perplexity\n\nclient = Perplexity()\nsnapshot_as_of = datetime.now(timezone.utc) - timedelta(days=30)\n\nsearch = client.search.create(\n    query=\"latest stable Python release\",\n    snapshot_as_of=snapshot_as_of,\n    search_domain_filter=[\"python.org\"],\n    max_results=5,\n)\n\nfor result in search.results:\n    print(f\"{result.title}: {result.url}\")\n```\n\n若要用同一截止点阅读这些页面的全文，把搜索得到的 URL 交给 Context API，并传入同一个 `snapshot_as_of`（文档示例在搜索有结果时才调用）：\n\n```python\nif search.results:\n    response = client.context.create(\n        urls=[result.url for result in search.results],\n        snapshot_as_of=snapshot_as_of,\n    )\n    for result in response.results:\n        if result.status.type == \"ok\":\n            print(result.url, result.metadata.fetched_at)\n```\n\n也可用 curl 直接请求 `https://api.perplexity.ai/search`，在 JSON 体里提供 `snapshot_as_of`。文档提醒：curl 示例里的时间是固定值，请改成最近 365 天内的时点。\n\n### 相关链接\n\n- 官博：[Freeze the web with Perplexity Time Machine](https://www.perplexity.ai/hub/blog/freeze-the-web-with-perplexity-time-machine)（2026-11-25）\n- 文档：[Time Machine](https://docs.perplexity.ai/docs/search/time-machine)\n- 官方介绍帖：https://x.com/perplexitydevs/status/2125676416834605488\n"
