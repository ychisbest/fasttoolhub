intro: "**Microsoft IQ** 是微软在 2026 年 11 月 17 日 Ignite 上宣布的企业上下文管理平台。Azure 博客 [Introducing the new Microsoft IQ](https://azure.microsoft.com/en-us/blog/introducing-the-new-microsoft-iq-putting-your-organizations-intelligence-to-work-in-every-agent/) 开篇就写：今天的前沿模型谁都能用、而且每隔几周就会进步，真正让一个组织与众不同的，是模型周围那些属于自己的东西——人们怎么工作、业务流程、机构知识，以及 CRM 等业务系统里的数据。Microsoft IQ 要做的，就是帮组织把这些“自己的智力”整理出来，并交给各类 agent 使用。\n\n官方把它写成四块能力的合体：**Work IQ** 提供人如何工作的上下文（文档、对话、协作和既有决策），**Fabric IQ** 提供受治理的业务数据、实体、关系和规则，**Foundry IQ** 提供政策与权威文档这类机构知识，**Web IQ** 提供来自网络的及时上下文。再加上 350 多个第三方连接器，以及可被多个 agent、团队和平台继承的 business plugins。插件可以在 Microsoft Copilot、GitHub Copilot、经 MCP 接入的 Microsoft Foundry，以及 ChatGPT、Claude 的市场里使用。\n\n本条记录的是这次被正式命名并推向一般可用的伞形产品名 Microsoft IQ。不要把它和早已存在的单个 Work IQ / Fabric IQ 功能、也不要和无关的模型名（例如 IQuest-Q1）混为一谈。"
explain: "微软的论点是：模型本身正在迅速商品化，组织的独特优势在于自己的上下文能否被 agent 稳定、可治理地用上。Microsoft IQ 把分散在 Microsoft 365、Fabric、Foundry 和网页里的上下文收成一套可复用的企业智力，再用 business plugins 把“该用哪些知识、技能、工具和权威来源”固化下来，让下一次任务不必从头配置。\n\n同一篇文章还写到各组件的进展，例如 Work IQ 里面向 CRM/ERP 的 Business Applications、Retrieve、实时会议上下文、长时任务和 agent-to-agent 支持均宣布一般可用；Foundry IQ 里出现了知识图谱预览，以及名为 **Microsoft Retriever 1** 的检索模型预览；Web IQ 对所有 Azure 客户开放，并给出按调用计费的起点价格。这些是同一平台下的能力更新，本词条不以它们各自另立条目，除非日后有独立产品化的正式发布。\n\nMicrosoft IQ 不是一个新的通用大模型，而是把组织上下文交给各种模型与 agent 使用的平台层。也不要和同场 Ignite 宣布的 Microsoft Perception、Copilot Home 或 MAI 模型系列当成同一个名字。"
usage: "从 [Azure 官方博客](https://azure.microsoft.com/en-us/blog/introducing-the-new-microsoft-iq-putting-your-organizations-intelligence-to-work-in-every-agent/) 了解定位，再按微软文档查看如何在 Copilot、GitHub Copilot、Foundry 或经 MCP 接入的第三方助手里启用上下文、连接器和 business plugins。典型用法是：先整理本组织要被 agent 继承的知识、流程和工具，做成受治理的插件，再让不同团队的 agent 共用同一套上下文，而不是每个应用各自接一遍数据源。\n\n评估时应看它实际能接到哪些系统、权限是否按人裁剪、插件能否在模型更换后仍然复用，以及 Web IQ、Foundry IQ Serverless 等计费项如何叠加。许可、区域和仍处预览的功能以当时的管理中心与官方文档为准。\n\n如果只是在 Copilot 里问一句公司文档的问题，或只用 Fabric 的某个语义模型，那还不是这个新的伞形产品名本身。"
