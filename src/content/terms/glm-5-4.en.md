At 04:18 UTC, Z.ai lead [@ZixuanLi_](https://x.com/ZixuanLi_/status/2124719275864670681) said GLM-5.4 was **available to all GLM Coding Plan users**, with new vision capabilities, stronger all-round coding, and a **50%** higher weekly quota than **GLM-5.3** for users who have weekly caps. At 10:27 UTC, the official account [@Zai_org](https://x.com/Zai_org/status/2124811995912286352) posted the technical introduction *Introducing GLM-5.4: Generalized Coding with Our First Loop Transformer*, alongside the research post: [z.ai/blog/glm-5.4](https://z.ai/blog/glm-5.4). That post highlights looping existing layers in the GLM-5 base for deeper reasoning, pushing past conventional coding into video, games, 3D shaders and CAD, and adding vision for stronger visual coding.\n\nThe blog’s core specs: at about **750B** scale, it **loops 28 layers** of the GLM-5 base for **two iterations**; the company says the result reaches intelligence comparable to **2T–3T**-parameter models; context is designed at million-token scale (the deployment discussion uses a **1M** context as the example). At announcement, the API was listed as coming soon, and open weights were planned only after necessary safety hardening.\n"
explain: "## What problem it targets\n\nThe blog restates a point from the GLM-5.3 technical post: memory-heavy work benefits more from parameters, reasoning-heavy work from effective compute. Large-scale software engineering, cybersecurity, 3D modeling and physical control are ultra-long causal-chain tasks. They need multi-step inference and global consistency; stacking parameters and memorizing data is not enough. GLM-5.4 uses looped depth so the model can reason more deeply without a matching jump in parameter count.\n\n## How the Loop Transformer is built\n\nIn a standard Transformer each layer runs once per forward pass. A Loop Transformer runs a block of **weight-shared** layers for several iterations, refining the previous hidden state. The idea goes back to the 2018 Universal Transformer and later recurrent-depth / looped LM work. The blog argues that looped models trained from scratch still lag unshared models under the same pre-training compute. So GLM-5.4 is **not trained as a looped model from scratch**. It adapts an already pre-trained GLM-5 base into a Loop Transformer with continued training, raising the ceiling at relatively modest extra compute.\n\nAt roughly 750B scale the team made three engineering changes to balance quality and serving cost:\n\n- **Gated progressive updates.** Turning middle layers of an existing model into multi-pass loops and overwriting hidden states can explode activation norms, so later layers see out-of-distribution representations. GLM-5.4 adds per-token, per-iteration gates that write candidate updates back into the residual stream proportionally. After training, the first pass is conservative and builds global context; the second opens the gates for full updates; on harder tokens the first pass writes more aggressively.\n- **Hybrid KV cache (global sharing plus an independent sliding window).** Keeping a full KV cache per loop would multiply memory with the iteration count. The second loop reuses the sparse KV selected in the first pass and keeps its newly generated KV in a sliding window, so an extra loop costs about one window rather than a full context cache. The blog says this keeps the serving-cost increase over GLM-5.3 under control at 1M context.\n- **Sparse attention index reuse.** The base model uses sparse attention. The second loop reuses the attention indices from the first loop’s indexer, with no extra indexing work. The company says this performs almost the same as recomputing indices every pass.\n\n## Vendor-reported capabilities and limits\n\nThe team says it validated the loop architecture on 1B, 4B, 30B and 750B bases. On a 30B model with the same architecture as the 750B base, an iso-parameter comparison with only about **10%** more total training compute showed clearer gains on long-horizon reasoning, and average output length on benchmarks such as GPQA-Diamond and MMLU-Pro fell by about 10–14%—some of the reasoning moves from explicit chain-of-thought into the implicit depth of the loop. Exact scores are in the blog charts and are not restated here.\n\nFor inference, the company claims up to about **200 tokens/s** off-peak and about **70–80 tokens/s** at peak, with kernel fusion and other systems work to support the multi-pass design.\n\nOn the product side, GLM-5.4 treats coding as the substrate for broader capabilities. Official demos include generating and editing video (a self-narrated Hello World music video), engineering-grade six-axis arm modeling in FreeCAD, building a complete game with movement, physics, maps, combat and art, and an interactive 3D experience from mathematical geometry and custom GLSL shaders. These are vendor demos, not guaranteed performance in arbitrary settings.\n\nThe blog also states a limitation: the model can get stuck in overly long “marathon thinking” loops, though that extended reflection and self-correction is said to keep improving accuracy beyond what the parameter count would suggest.\n"
