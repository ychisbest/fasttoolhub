It tests how well coding agents such as Claude Code and Codex can use your APIs, docs, MCPs, and skills on real-world tasks. explain: "## What the company claims\n\nThe account below comes from the 25 November [official blog](https://www.together.ai/blog/introducing-hurdle-run-agent-evals-on-your-api-skills-and-docs) and the launch tweet. It is the vendor’s description.\n\nHurdle treats a task as a prompt a developer would hand to an agent, then runs that task across the agents, models, and conditions you specify, records each session, and scores it. You can use one scoring method or mix them:\n\n- **Code checks**: Assertions about the run, such as which API requests the agent must make and which files or data it should produce.\n- **Guards**: Rules that block actions the agent is not allowed to take (for example, creating a paid cluster) while the run is in progress; an attempt counts as a failure. The post states that request-level checks and guards work only on sandboxed runs.\n- **Judge**: An LLM that reviews the recorded session against a rubric you write in plain language and decides whether the agent passed.\n\nThe same task can also run under different **conditions**—for example with and without your MCP server or skill installed—so you can see whether those extras help or hurt. A suite runs every task against every agent/model combination you list, and can repeat each combination to produce an overall pass rate.\n\nThe blog’s example task is “list GPU cluster regions and instance types, print the cheapest option and the reservation command, but do not actually reserve anything.” It shows `defineChecks`, `defineGuard`, and `defineSuite` for a request check, a guard that blocks cluster creation, and the list of tasks, models, conditions, and repeats. A suite can set `verdict` to `hybrid` so a run passes only if both the code checks and the judge pass.\n\n### Local runs and sandboxed runs\n\nThe post describes two execution modes. **Local runs** are for quick tests on tasks you trust: Hurdle starts the `claude` or `codex` CLI on your machine in a temporary workspace, hands it the task prompt and files, and records the session. Each agent starts with a clean config, so your everyday Claude Code or Codex setup does not affect the results. The caveats are that Hurdle cannot see or block the agent’s API requests, so guards and request checks are unavailable, and the agent runs as you, with access to local files and real API keys.\n\n**Sandboxed runs** are for production evaluations. The company says Hurdle uses the Together Sandbox API to spin up an isolated environment for each run, where the agent can execute code, install dependencies, and call APIs without touching your machine. On start, Hurdle launches a local proxy called Guardian and opens a WebSocket to Together, which boots a fresh sandbox for that run.\n\nThese details are the company’s own description, not a third-party reproduction.\n"
usage: "## How to try it\n\nThe official blog gives these start and review commands:\n\n```bash\nnpx hurdle init\nnpx hurdle run --view\nnpx hurdle view\n```\n\n`npx hurdle run` executes the suite; `--view` opens the results viewer when it finishes. The company says results are saved under `.hurdle/` in your project directory, and you can reopen them later with `npx hurdle view`. Checks show up in the terminal as each run finishes, marked passed, failed, or skipped. The viewer surfaces the headline pass rate, average duration, and average cost per run, then breaks results down by task and condition; opening a run shows the full transcript, tool calls, API requests, and the outcome of every check and the judge.\n\nSee the “Example task” and “The eval suite” sections of the blog, and the [GitHub repository](https://github.com/togethercomputer/hurdle), for the full suite, check, and guard examples.\n\n### Links\n\n- Official blog: [Introducing Hurdle: Run agent evals on your API, skills, and docs](https://www.together.ai/blog/introducing-hurdle-run-agent-evals-on-your-api-skills-and-docs) (25 November 2026)\n- Code: [togethercomputer/hurdle](https://github.com/togethercomputer/hurdle)\n- Official post: https://x.com/togethercompute/status/2125709140425363612\n"
