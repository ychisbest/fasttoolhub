The official account [@nestframework](https://x.com/nestframework) posted [Introducing the official NestJS agent skills!](https://x.com/nestframework/status/2123741121482489930) at 2026-11-20T11:31:55Z (19:31 Beijing time), with the install command `npx @nestjs/skills add`. The post says the skills are built into `nest new` and work with Claude Code, Codex, Cursor and more.\n\nThe companion repository is [nestjs/agent-skills](https://github.com/nestjs/agent-skills). The npm package [@nestjs/skills](https://www.npmjs.com/package/@nestjs/skills) was created at 2026-11-20T08:10:00Z; 0.1.0 was published at 08:11 UTC, and 0.1.1 in this window at 11:03:42Z. The package description says it is for building and extending NestJS applications with coding agents, in the [Agent Skills](https://agentskills.io) format.\n\nThis entry is for the official pack named **NestJS Skills** (the package and command are `@nestjs/skills`). It is not the NestJS framework itself, not `@nestjs/ai`, and not a community-maintained NestJS skills repo."
explain: "According to the npm readme, the pack fills gaps in a model’s training data: current APIs that are newer than the model, Nest’s first-party packages, and mistakes that can still pass tests — for example a sign-in that leaks whether an email exists, `@IsOptional()` letting `null` through to a 500, a rate limiter that never sees the user, or an event stream that outlives a revoked key. Each skill is a folder with a `SKILL.md` plus longer recipes in `references/`; the official text says every recipe was run on the released packages.\n\nThe published skills are: `nestjs` (creating or extending an app, layout, modules, docs, and common mistakes), `nestjs-feature` (endpoints, validation, status codes, SSE, and related HTTP options), `nestjs-auth` (`@nestjs/authentication` and `@nestjs/authorization`), `nestjs-data` (`@nestjs/drizzle` and `@nestjs/typeorm`, migrations, paging, and transactions), `nestjs-testing` (unit, service, and end-to-end tests), and `nestjs-production` (configuration, logs, NestJS Observe, health checks, rate limiting, OpenAPI, shutdown, and deployment). Agents load a skill when its description matches the task, so you do not have to invoke each one by hand.\n\n`npx @nestjs/skills add` copies the skills into `.agents/skills/` by default, which Codex, Cursor, and other Agent Skills readers use. `--agent claude` writes to `.claude/skills/`, and `--agent cursor` writes to the Cursor location. The official post also says the skills are built into `nest new`. This entry follows that post and the npm readme, and does not treat unstated editor support or star counts as facts."
usage: "The official install command is `npx @nestjs/skills add`, which writes to `.agents/skills/` by default. Add `--agent claude` for Claude Code’s `.claude/skills/` folder, or `--agent cursor` for Cursor’s location. New projects can also rely on `nest new`, which the official post says already includes the skills. See [nestjs/agent-skills](https://github.com/nestjs/agent-skills) and [@nestjs/skills](https://www.npmjs.com/package/@nestjs/skills).\n\nUse the pack when you want a coding agent to follow current official NestJS APIs and first-party packages while changing code, writing tests, or preparing a production app. It does not replace the NestJS framework or the `@nestjs/ai` runtime. Skills are loaded when their descriptions match the task. Versions, default install paths, and compatible agents are whatever the official docs and npm package say at the time. This page only restates the official post and npm readme, and does not treat community NestJS skills as this official pack."
