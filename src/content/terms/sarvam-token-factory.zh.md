intro: "**Sarvam Token Factory** 是印度 AI 公司 [Sarvam](https://www.sarvam.ai/) 在 2026 年 11 月 16 日向所有人开放的推理服务。官方账号 [@SarvamAI](https://x.com/SarvamAI/status/2122323115535720921) 于 2026-11-16T13:37:16Z（北京时间 2026 年 11 月 16 日 21:37:16）发帖：“Today, we are launching Sarvam Token Factory for everyone. explain: "Token Factory 的定位是推理平台，而不是一个新的基础模型名称。博文把它概括为：成本上对所服务的每个模型提供具有全球竞争力的定价；性能上把公司的推理优化集中到 Sarvam 105B，官方称对话场景下首 token 时间为 0.2 秒、单用户吞吐 330 tokens/s；时延上，Gemma 4 31B 在 10K token 提示、从孟买测量时首 token 0.40 秒，并称比当时唯一的其他提供商快 5 倍（对照为 2.00 秒），输出速度 308 tokens/s 对 193 tokens/s；吞吐上，Kimi K3.1 Pro 被称在同等每用户速度下，每 GPU 的 token 数可达 InferenceX 已公布结果的 1.9 倍（编码任务）。这些数字均来自官方博文，测量说明写的是：Gemma 对照为 72 小时中位数、客户端在 AWS Mumbai，对方便取其各档中该指标最好的一档。\n\n价格方面，博文给出 DeepSeek V4.1 Flash 的入门价：Standard 为每百万 input token ₹14、output token ₹55；Interactive 为 ₹25 / ₹105。两个端点都按模型原生精度提供。官方还描述了一套三层缓存，带 cache-aware routing 与针对新注意力架构的 admission；并称在 DeepSeek V4.1 Flash 上每天服务超过 4,500 亿 token，其中 95.7% 的 prompt token 来自缓存。博文后半部分用较多篇幅写他们如何用分析器、服务器校准过的模拟器和评估套件做栈上实验，并由工程师在上线前批准；同时感谢 vLLM、SGLang、Dynamo、Mooncake、NIXL、DeepEP、DeepGEMM 和 FlashInfer 等上游工作。\n\n对企业，官方强调可选模型更多、并且可以“拥有自己的 AI 栈、不被锁定”。除了 Token Factory 云服务，同一套优化栈也已用于关键机构的本地部署，并作为企业选项提供。数据驻留在印度、用卢比计价，是新闻报道与官方材料反复提到的差异点。"
usage: "按官方说明，Sarvam Token Factory 即日起对开发者和企业开放，通过一套 OpenAI 兼容 API 调用目录中的模型，并会继续在新开源权重模型发布当天跟进、按需求扩容。开始使用的入口在官方介绍帖的 “Start building” 链接，指向 Indus 上的 Token Factory 主页（[indus.sarvam.ai](https://indus.sarvam.ai/login?return_to=%2Ftoken-factory%2Fhome)）；更完整的产品说明以 [官方博文](https://www.sarvam.ai/blogs/sarvam-token-factory) 为准。\n\n选型时，博文把几个端点写得很具体：需要编码代理、追求较高每用户速度时，DeepSeek V4.1 Flash 的 Interactive 端点官方标称为约 200 tokens/s；后台或批处理则可走 Standard，价格更接近入门档。实时印地语及其他印度语言对话，官方主推 Gemma 4 31B，并给出从孟买测量的首 token 与吞吐对照。自有模型 Sarvam 105B 被写成对话场景下成本与速度的组合点。若不能满足云上调用，官方称也可把同一套推理优化栈做 on-premise 部署。\n\n调用协议是 OpenAI 兼容 API，因此现有走 OpenAI 接口的应用、代理和网关，理论上只需改 base URL、模型名和密钥即可切换；具体模型目录、配额与鉴权以官网当时公布的目录为准，本页不编造未在官方材料中出现的端点路径或密钥申请步骤。官方也写到会继续为在 Token Factory 上构建和部署代理提供更多工具。"
