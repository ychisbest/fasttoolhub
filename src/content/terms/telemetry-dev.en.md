intro: "**telemetry.dev** is an **LLM observability platform for AI applications and agents**, built on **OpenTelemetry**. It launched on **Product Hunt on October 31, 2026**, finishing **#3 Product of the Day** with about 128 upvotes; maker Ephraim Duncan promoted the launch on X.\n\nThe product shows **each run of an AI agent as a single trace**. Every model call, tool call and retrieval becomes a **span** with its duration, token usage, cost and error, so when an agent breaks in production you can see which step failed and what the run cost. The launch added **prompt management**, **evals**, **alerts**, a **CLI** and an **MCP server**."
explain: "## Key features\n\n- **Traces and spans**: one trace per request or agent run; model calls, tool steps and retrievals are spans with latency, tokens, cost and errors.\n- **Prompt management**: change prompts without redeploying.\n- **Evals**: run a new prompt version on a dataset and compare scores with production traces before going live.\n- **Alerts**: notifications when errors pile up, costs spike, or an agent gets stuck in a loop.\n- **CLI + MCP server**: your coding agent (Claude Code, Codex, etc.) can read your traces directly.\n- **Integrations**: TypeScript and Python SDKs for OpenAI, Anthropic, the Vercel AI SDK, LangChain and more, or plug in an existing OpenTelemetry exporter.\n\n## Pricing\n\nA free plan includes **30,000 ingestion units per month** (one per span, log record or metric data point) with no credit card; paid Pro plans add more volume.\n\n## How it compares\n\nIt competes with tools like Langfuse, LangSmith, Helicone and Arize Phoenix. Its pitch is being OpenTelemetry-native and agent-focused, with loop and cost alerts plus an MCP server for agent self-debugging."
